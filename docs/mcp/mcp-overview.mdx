MCP (Model Context Protocol) lets Cline use external tools and data sources through MCP servers.

## What MCP gives you

- Connect Cline to external APIs and services
- Add custom tools beyond built-in Cline tools
- Use either local servers or remote hosted servers

## Quick start

1. Open **MCP Servers** in Cline
2. Add a local server manually, or connect to a hosted remote server
3. Configure credentials/environment variables
4. Verify tools appear and test one tool call

## Add servers

### Manual config

Edit your MCP config file and add either:

- **CLI:** `~/.cline/data/settings/cline_mcp_settings.json` (override with the `CLINE_MCP_SETTINGS_PATH` env var)
- **IDE extensions:**
  1. In the Cline panel, click the **MCP Servers** icon (stacked server icon in the top toolbar).
  2. Open the **Configure** tab.
  3. Click **Configure MCP Servers** (button near the bottom).
  4. This opens the MCP settings JSON used by the extension; add/update entries under `mcpServers`.
  - If you're adding a hosted endpoint (instead of editing JSON directly), use the **Remote Servers** tab:
    1. Enter **Server Name** (any unique label).
    2. Enter **Server URL** (full endpoint URL).
    3. Choose **Transport Type**:
       - **Streamable HTTP** (recommended)
       - **SSE (Legacy)**
    4. Click **Add Server**.

  - Server config shape:
    - **Local (STDIO)** server using `command` + `args`
    - **Remote (HTTP/SSE)** server using `url`

### CLI MCP wizard

Run this in your terminal:

```bash
cline mcp
```

The wizard supports:

| Action | Description |
|---|---|
| List servers | Show configured servers and enabled/disabled status |
| Add server | Create a new MCP server entry |
| Edit server | Modify an existing server |
| Enable/disable server | Toggle a server without deleting it |
| Authorize OAuth | Run or rerun browser authorization for a remote server |
| Delete server | Remove a server permanently |

When adding a server, the CLI prompts for server name, transport type, command/args (for stdio), or URL/headers (for remote transports).

To add or remove a server from a script, skip the menu:

```bash
cline mcp add files --yes -- npx -y @modelcontextprotocol/server-filesystem .
cline mcp add docs https://example.com/mcp --transport http --header "Authorization: Bearer TOKEN" --yes
cline mcp remove docs
```

Without `--yes`, `cline mcp add` opens the add wizard with those fields filled in.

## Configuration examples

### Local server (STDIO)

```json
{
  "mcpServers": {
    "local-server": {
      "command": "node",
      "args": ["/path/to/server.js"],
      "env": {
        "API_KEY": "your_api_key"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

### Remote server (Streamable HTTP)

```json
{
  "mcpServers": {
    "remote-server": {
      "type": "streamableHttp",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token"
      },
      "disabled": false,
      "autoApprove": []
    }
  }
}
```

The `type` field selects the transport. Omitting it defaults to the legacy `sse` transport for backward compatibility, so set `"type": "streamableHttp"` explicitly for the recommended transport. Use `"type": "sse"` only for legacy SSE servers.

## Transport types

- **STDIO**: local process, lower latency, simpler local setup
- **Remote HTTP/SSE**: hosted endpoint, centralized deployment, supports multi-client usage

Use STDIO for local tools and remote transport for shared hosted services.

## Managing servers

In MCP settings you can:

- Enable/disable servers
- Restart unresponsive servers
- Set request timeouts
- Remove servers

## MCP servers configured in VS Code

In the VS Code extension, Cerebriline also offers the tools of every MCP server **VS Code itself** is running: the ones in VS Code's own MCP configuration (`mcp.json`, listed by **MCP: List Servers**), not in Cerebriline's MCP settings. This is on by default and needs no setup. If VS Code has the server running, Cerebriline offers its tools.

VS Code has already started and authenticated those servers, so Cerebriline calls their tools through VS Code (`vscode.lm.invokeTool`) instead of connecting to them itself. That also reaches servers Cerebriline cannot connect to on its own. Figma's MCP server, for example, advertises client registration and then refuses it, so Cerebriline can never obtain a client id for it, but VS Code already holds a token.

<Note>
  VS Code only. The CLI and other hosts have no VS Code to borrow from and offer only the servers in their own MCP settings.
</Note>

### How they appear

- **To the model:** each tool is named `vscode__` followed by VS Code's id for it without its `mcp_` prefix, for example `vscode__figma_get_code`. The prefix keeps them apart from a server you have also configured in Cerebriline, so the same server set up in both places shows up twice, under two names.
- **In Manage MCP Servers:** all of them sit under one entry called **`vscode`**, whatever server they come from. VS Code does not tell extensions which server a tool belongs to, so they cannot be grouped per server. The entry shows only when VS Code reports at least one MCP tool.
- **Results and stopping:** results come back as text, like any other MCP tool's. Stopping the task cancels a call that is still running.

### Controls

| Control | Where | What it does |
|---|---|---|
| On/off | The toggle on the `vscode` entry, or the setting `cerebriline.vscodeMcpTools` (default `true`) | Stops or starts offering these tools to the model. The toggle and the setting are the same switch. |
| Auto-approve | The tick box per tool on the `vscode` entry, stored in `cerebriline.vscodeMcpAutoApprove` | Lets that tool run without asking. VS Code's own approval settings for the server are not visible to Cerebriline and are not inherited, so a tool you have not ticked asks every time. |
| Remove | In VS Code | The entry cannot be deleted from Cerebriline. The servers belong to VS Code, so remove them there, or switch the entry off. |

The name `vscode` is reserved for this entry. A server you name `vscode` in Cerebriline's own MCP settings is ignored, because its tools would collide with these.

### When they do not show up

1. Check that the server is configured in **VS Code**, not in Cerebriline's `cline_mcp_settings.json`.
2. Run **MCP: List Servers** and make sure the server is running and has loaded its tools. Start it from there if it is not.
3. Check that `cerebriline.vscodeMcpTools` is not set to `false`.
4. Start a new task. The tools are collected when a task starts, so a server started during a task is offered from the next one.

The extension log names what it found: `[VscodeLmMcpTools] Adopted N MCP tool(s) from VS Code: …`.

## Security basics

- Only install servers you trust
- Store secrets in environment variables
- Limit `autoApprove` to safe tools
- Review tool calls before approval

## Troubleshooting

| Issue | Fix |
|---|---|
| Server won't connect | Verify command/URL, server process status, and port |
| Missing tools | Confirm server started successfully and tools are exposed |
| Auth errors | Re-check API keys/tokens and required headers |
| Timeout errors | Increase MCP timeout and test server response directly |

## CLI

MCP also works in Cline CLI. Configure servers in CLI MCP settings and use the same server definitions.

To list servers without the wizard:

```bash
cline config mcp
cline config mcp --json
```
