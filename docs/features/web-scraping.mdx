With a [Firecrawl](https://github.com/firecrawl/firecrawl) endpoint, the model can search the web, list a site's pages, read a page, and crawl a site. Pages are read in a real browser, so pages built by JavaScript are read too.

It is **off by default**, and it takes two switches, because pages are fetched from the open web on your behalf:

1. **Settings > Features > Web scraping**: the endpoint's address, its key if it needs one, and how far a crawl may go. **Check** reads one page and shows what came back.
2. **Allow web scraping**, in the API configuration.

Without both, no web tool is ever offered to the model.

## Who may scrape

**Only for the librarian** is ticked by default. Then scraping is used by the [librarian](/features/library#books-from-the-web) alone, to make a book from web pages and to check it for news later.

Untick it and every task is offered the general `web_scrape` tool, whether the Library is on or not. The change takes effect in the next task.

| | Only for the librarian (default) | Unticked |
| --- | --- | --- |
| `web_scrape` | The librarian's: `search`, `map`, `read`. | The general one: `search`, `map`, `read`, `crawl`, and saving to files. Any task. |
| `library_web_book` | With the librarian on. | With the librarian on. |

## The tools

### `web_scrape`

| Action | What it does | What it takes |
| --- | --- | --- |
| `search` | Finds pages for a topic, with their titles and what they are about. | `query`; `limit` (results, default 10, at most 50). |
| `map` | Lists the pages of a site by their links, without reading them. | `url`; `limit` (links, default 200, at most 2,000). |
| `read` | Returns one page as markdown. | `url`; `max_chars` (how much is returned, default 12,000). General tool: `save_to`, a file to write the whole page to; then only its headings are returned. |
| `crawl` | Reads a page and the pages it links to, and saves the site under a folder. General tool only. | `url`, `save_to` (a folder, required), `content`, `depth`, `limit`, `whole_site`, `include_paths`, `exclude_paths`. |

A map of a site that has one page says so, and names the other sites the page links to.

### `library_web_book`

The librarian's tool for making a book from web pages and keeping it up to date. It is described under [Books from the web](/features/library#books-from-the-web). It takes `links`, `depth` and `limit`, and reads the pages into the Library, not into files.

## Crawling a site into files

A crawl saves a site into a folder of the workspace. By default it saves **the site itself**, unaltered, so the pages can be reworked or used as the source of new ones:

> Scrape https://example.com into `source/example`.

For each page:

| File | What it is |
| --- | --- |
| `example.com/docs/plugins.html` | The page exactly as the site served it, byte for byte. |
| `example.com/docs/plugins.rendered.html` | The page as the browser held it after its scripts ran. On a site built by JavaScript the served page is a shell of a few lines, and this one is the page you see. |
| `example.com/docs/plugins.md` | A markdown reading of the page, with its address and title at the top. |

And once for the whole crawl, every file the pages use: stylesheets, scripts, pictures, fonts, icons and media, each at the path the site has it (`example.com/assets/app.js`). Files from other hosts, such as a font service, go under that host's own folder (`fonts.gstatic.com/...`). Fonts and pictures named inside a stylesheet are fetched too.

`index.md` in the folder lists every page in each of its forms, every file fetched, and everything that could not be read or fetched with the reason.

What to know:

- **Nothing is rewritten.** Links inside a saved page still point where the site pointed them. A page that asks for `/assets/app.js` will not find it when opened straight from disk; the files are there to be worked from.
- **The pages come through the scraping endpoint; the other files do not.** Firecrawl returns a page's content, not its stylesheets. Those are fetched directly from the site by the machine the extension runs on.
- If the site refuses the direct request for a page, only its rendered form is saved, as `.html`, and the result says so.
- A file is fetched once however many pages use it. One file may be up to 25 MB, and one crawl fetches at most 2,000 files and 300 MB; what is left out is counted in the result.
- The files are not returned to the model, so a large crawl does not fill its context. It reads the ones it needs afterwards.
- `save_to` has to be inside the workspace.

### Text only

For knowledge you want kept as notes, ask for the text:

> Crawl the docs of https://example.com/docs into `reference/example` as text only, then summarise how its plugin system works.

The model sets `content` to `text`, and the crawl saves the markdown files and `index.md` alone. Nothing is fetched from the site directly.

## Depth and page count

Two numbers decide how far a crawl goes.

- **Depth** is how many links away from the starting page the crawl follows. 0 reads the starting page only. 1 also reads the pages it links to. 2 also reads the pages those link to.
- **Page count** is the most pages one call reads, whatever the depth.

### Defaults

| | Depth | Pages |
| --- | --- | --- |
| `web_scrape` `crawl`, when the model names none | 1 | 25 |
| `library_web_book`, when the model names none | 0: only the links given | one per link given; with a depth, the most your setting allows |
| The most either can get (your settings) | 3 | 100 |

The last row is **Settings > Features > Web scraping**: "Links deep a crawl may follow" (0 to 10) and "Pages one crawl or book may read in a call" (1 to 5,000). The model can ask for less than these, never more: a request for 500 pages with a setting of 100 reads 100.

### Asking for them

Say the numbers in your message. The model passes them to the tool as `depth` and `limit`:

> Crawl https://example.com/docs into `reference/example`, 2 links deep, at most 60 pages.

> Scrape only the front page of https://example.com into `source/example`.

> Make a book from https://example.com/guide, following its links one level, no more than 40 pages.

If you name no numbers, the defaults above apply. To go beyond 3 links deep or 100 pages in one call, raise the two settings first.

### Where a crawl goes

A crawl stays **below the address it starts from**: started at `https://example.com/docs/`, it reads `https://example.com/docs/...` and nothing else on the site. Started at one page such as `/docs/intro`, it usually reads that page alone.

- Start at the section you want, or at the front page for the whole site.
- Or say "the whole site": the model sets `whole_site`, and the crawl follows links anywhere on the same site.
- "Only the API pages" or "skip the blog" become `include_paths` and `exclude_paths`, regular expressions matched against each page's path.

> Crawl the whole site of https://example.com into `site`, skip everything under /blog, at most 80 pages.

Links to other sites are never followed.

### What the result says

When a crawl ends, the tool tells the model which of three things happened, and the model can tell you:

- **The page limit was reached**: the site may have more. Ask again with a higher count, or raise the setting.
- **That is the whole site from this address**: every page the crawled pages link to was read.
- **N more pages of this site are linked and were not read**, with examples: they are deeper than the depth asked for, or not below the starting address. Ask for more depth, or for the whole site.

## Limits

- The general tool is the lead's. Agents the lead starts are not offered it.
- `read` saves markdown only. To save one page with its files, crawl it with a depth of 0.
- Content that only loads after a click or a scroll, and files a script asks for by a name it builds at run time, are not found.
- The markdown is converted from the page's HTML by Cerebriline, which keeps fenced code blocks and their language.

## CLI

`--web-scrape` (or `CLINE_WEB_SCRAPE=1`) offers the general tool, writing under the folder the run is in. The endpoint is named by `CLINE_SCRAPE_BASE_URL`, with `CLINE_SCRAPE_API_KEY` when it needs one. `CLINE_SCRAPE_MAX_PAGES` (default 100) and `CLINE_SCRAPE_MAX_DEPTH` (default 3) are the two limits. Without the switch, scraping is the librarian's only (`--librarian`).
