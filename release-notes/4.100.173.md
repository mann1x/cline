## One profile on the main model and an agent node stays saved

- **A profile no longer looks changed when you use it on both the main model
  and an agent node.** A profile saved from an Agents node, or from the Vision
  or Escalation tab, stored an extra copy of the model name that profiles
  saved from Plan or Act did not have. The unsaved-changes check counted that
  copy as a difference. So the same profile always asked to be updated on
  whichever kind of tab it had not been saved from, and updating it there
  moved the prompt to the other side. The check now ignores that field, and
  profiles are saved without it. The model is still recorded in the profile's
  own model fields.

## One call launches the whole fan-out; a dead node steps aside

- **`agents` entries take a `count`.** `{"type": "code-verifier", "task": "…",
  "count": 15}` is 15 agents, each with its own row and report. "15 of each of
  five agents" is now one `spawn_agent` call with five entries.
- **The delegation tools say when a call returns.** A `spawn_agent` call
  returns only when every agent in it has finished, and the lead's next
  message waits for it. Asked for 75 agents, qwen sent five calls of 15, each
  in its own message, so the second batch started only after the first had
  finished. The descriptions now say this and point to the one-call form: a
  configured agent by `type`, several of one kind with `count`. The
  configured-agent tools point there too.
- **qwen's template no longer describes `spawn_agent` as one agent per call.**
  Its `spawn_agent` section started with a model-written note listing only
  `systemPrompt` and `task`, ahead of the built-in text. That section now uses
  the built-in text alone.
- **A node whose gateway has nothing behind it leaves the rotation.** When the
  route to Node1 went down, every agent sent there came back after about 6 s
  as an empty run reading "Bad Gateway". The node had answered, so it counted
  as up, and the queue kept sending agents to it: 13 were lost in two minutes
  while Node2 had room. A 502 or 504 from the node now puts it into the same
  cool-off as a node that can't be reached, and the agent goes to another node.
  The agent's row says why it is waiting.
