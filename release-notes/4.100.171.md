## Agent lists sent as text are read, and a counted swarm shows every agent

- **`spawn_agent` reads an `agents` list sent as text.** qwen sent `agents` as
  a string, twice in a row, with the call's `"merge": true` run on after the
  list inside it. The tool failed with `a.map is not a function`, so the model
  gave up on the list and ran one task 15 times instead of the 15 different
  jobs it had planned. The tool now reads the list, and takes the fields that
  ran on after it (`merge`, `count`, `knowledge` and similar) when the call did
  not set them itself. Text that still doesn't parse is refused with an error
  saying how to send it. An entry with no `task` is refused by its index.
- **A swarm of one task run N times shows N agents.** `spawn_agent` with
  `merge: true`, one `task` and a numeric `count` got a single row, so 15
  running agents looked like one. Each worker now has its own row, stop button
  and result, the way a `tasks` list already did. `count: "max"` still has one
  row, since the engine decides how many run.
