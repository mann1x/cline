## The node label never reached the placement engine

4.100.159 named the nodes, and the chat went on printing storage keys. The
host set the label; the mapping that hands the node list to the placement
engine rebuilt each node from four fields by name, and dropped it one layer
short. The badge still read `on primary`.

Every test passed, which is the part worth recording: they hand the placement
a label directly, so they proved the placement *carries* one and never that
the runtime *gives* it one. It is a spread now rather than a longer list of
fields — a list of fields to copy is a list that goes stale on the next field.

## A node that cannot run the agent puts it back in the queue

    {"text":"model 'ornith-27b_tb:iq4_xs-128k' not found","iterations":1,
     "finishReason":"error","usage":{"inputTokens":0,"outputTokens":0},
     "nodeId":"node-mucvow61"}

The server holds 193 models and not that one. In a five-agent fan-out two
agents died on that node, a third died when the lead retried straight back
into it, and two healthy nodes sat idle throughout. On screen it was three
empty reports.

Two reasons nothing caught it. The cool-off that takes a node out of the
rotation reads "unreachable" at the transport level, on purpose — a server
that answers is alive, and a rate limit or a context overflow says nothing
about the node. This server answered. And it did not throw: the sub-agent
*returned* an error result, so the clause that marks nodes down was never
entered.

A missing model is the one refusal that is neither transient nor the agent's.
It spends nothing, so there is no work to lose and no side effect to repeat,
and it will answer the same way for every agent after this one. So the agent
goes back in the queue and is placed again, and the node leaves the rotation
for ten minutes rather than thirty seconds — a tag the server has never heard
of does not appear on its own. It stays a cool-off rather than a removal
because pulling the model mid-session is an ordinary thing to do.

Bounded at three nodes: a request that fails the same way everywhere is
reported as its own failure rather than walked around the rotation taking
every node down on the way past. And re-placing requires that the attempt
spent nothing — a failure that burned tokens may have edited a file, and
running it again elsewhere would do it twice.
