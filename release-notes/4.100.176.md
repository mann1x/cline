## Swarm admission and a stalled swarm

- **The PolyKV throughput floor is now applied.** The "Per-session throughput
  floor" was stored and shown but never sent to the engine, so the server ran
  at its own boot floor (5 tok/s): a profile asking for 15 got 60 agents at
  5 tok/s. The policy is now posted on every pool the swarm creates. A floor
  with no mode set is sent as `enforced`, so a new agent that would pull the
  mean below the floor is refused and waits in the queue instead of slowing
  everyone down.
- **A full owner no longer stalls its agents.** A swarm books its KV in owner
  windows. When one was full, its agents waited on it for up to 15 minutes,
  even with other owners of the same swarm nearly empty (seen with 75 agents:
  one owner at 77%, three at 3–8%, and no cells left on the server). A refused
  agent now moves to the owner with the most room. An owner whose last agent
  leaves is closed, which frees its window.
- **The PolyKV status strip shows the floors in force.** It shows the
  server's slot-growth floor and the admission floor on each pool, and says
  plainly when no pool has one.
- **Profiles:** Delete now asks before removing a profile. Copy on the
  profile picker (for example, right-click → Copy) copies the selected
  profile's name, ready for a "Save as…".
