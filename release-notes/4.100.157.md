## Parallel Sessions said the wrong thing on most panels

Three faults in one paragraph of copy, all reported from the opencoti panel.

**It described Ollama to everyone.** The text opened with
`OLLAMA_NUM_PARALLEL` whichever provider you were configuring — including
opencoti and llama.cpp, which have a `--parallel` flag instead, and the
hosted providers, which have neither. Each now names the thing that actually
sets it. The OpenAI-Compatible form names both cases, because that one entry
genuinely covers a local llama.cpp *and* a hosted endpoint and cannot tell
which you pointed it at.

**It said "1 to 10" beside a field you are meant to leave blank.** On an
opencoti with PolyKV admission or elastic slots, an empty field is how you
hand the decision to the engine — and a stated minimum of 1 reads as "blank
is 1", which is the opposite. The range no longer states a minimum, and what
an empty field means is spelled out for the case you are in, since the answer
is opposite on an elastic server and a fixed one.

**And it capped at 10.** That number was chosen for local llama.cpp servers
before elastic opencoti existed, and it ignored hosted plans, whose
concurrency is not ours to cap. It was low enough to be doing the choosing —
a profile found sitting at exactly 10. The ceiling is 64 now, wide enough
that only a typo reaches it. What a server will actually take is still the
server's answer; this field is a ceiling you opt into, and an empty one asks
for none.
