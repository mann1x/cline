## The agent panel fits on one row, and agents know they are paced

- **One row per agent.** The open agent's box now reads, on its first line:
  name, Stop, tool count, current tool, node, and generation speed
  (`~23 tok/s`). The model and context size moved to a quieter second line.
  Stop used to have a row of its own, and the node, tools and model another.
- **The node shows while the agent runs.** It is reported at placement.
  Before, it only arrived with the result, when it no longer explained a slow
  agent.
- **Queued agents read as queued.** An agent waiting for a node shows the clock
  and "queued" until a node takes it. Before, every agent read as running from
  the moment it was spawned, so 75 agents on nodes that take three looked like
  75 at work.
- **Launching many is described as safe.** `spawn_agent`, the configured
  `subagent_*` tools and `spawn_swarm` now say that the harness queues and paces
  agents, and that every call a job needs goes in one message. In the 75-agent
  run the lead argued five times over whether 75 calls was too many before it
  launched them together. A configured agent's tool also says that several
  calls are how to fan it out. The same lead rebuilt all five configured roles
  by hand on `spawn_agent`, reading "one call, one agent" as a reason not to
  use them.
- **Sub-agents are told to check with a tool.** The three agents that finished
  last in that run made no tool call. Each spent one ~30k-token thinking turn
  counting braces by hand, about 50 minutes at the speed it ran. The sub-agent
  preamble now says to run a parser, syntax check or test when one would
  settle the question.
