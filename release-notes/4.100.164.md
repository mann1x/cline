## Parallel conversations on one opencoti server share their prompt

Agents on a PolyKV node already shared their prefix. Conversations did not.
Every Cline session on the same opencoti server built a pool of its own from
its own system prompt. So the system prompt and the tool schemas, about a third
of the window, were prefilled and held once per conversation.

They could not have shared it anyway. The date and working directory sit twenty
lines into the system prompt, and the chat template renders the tools after
that text in the same turn. Two sessions in different folders, or on different
days, differed before the tools began, and nothing after the first difference
can be shared.

On opencoti the per-session parts now travel as a turn of their own:
platform, date, IDE, working directory, workspace rules, and the plan/act mode
contract. The system turn is then the same for every conversation, and the
engine holds it once:

    system prompt + tools   -> every conversation on the server, no owner
    + your environment      -> your conversation, inside your own window
    + the conversation

Measured on the 8240 server with three conversations in different folders and
modes: one shared root of 1,492 tokens and three sub-pools of their own. Each
window held 50, 485 and 58 tokens of its own instead of about 1,500. Nothing was
left on the server after the three ended.

The model reads the same words as before: the environment is an
`<environment>` block right after the system prompt. Every other provider gets
that block appended to the system prompt as one text.

Two limits, both on the engine side and being fixed there:
- The context-size check still counts the shared tokens against each window.
  Sharing therefore saves the prefill and the memory, but does not yet admit
  more sessions.
- On c7 a conversation's later turns report nothing shared.
