## Forty-nine of fifty-one agents stopped at one window

The lead fanned 51 agents out over two opencoti nodes. 49 came back empty or
"hit the output limit". The server said why:

    stopped: session allocation '1790137120308_fotu9' full
    (262144 cells, tree holds 262763) — compact the session

That id was the lead's. Every sub-agent inherited it, meant for telemetry, and
also sent it to the engine as its session. So all 51 were charged to the lead's
one 256k window. At about 12k tokens each it was full by the 21st agent, and
every agent after that was cut off a few tokens into each turn.

Each agent now runs in an engine session of its own. On a PolyKV node the agents
also stop paying for what they share. The engine holds a tree of pools inside
one owner window:

    system prompt + tools   -> every agent
    + shared knowledge      -> every agent given it
    + role instructions     -> every agent of that role
    + its own task          -> the agent, attached as a worker

Measured on the 8240 server with the same file: 50 agents × 2 turns, 100 of 100
turns completed, all in one 262k window that peaked at 164k. When the last agent
finished, nothing was left allocated. The same work as ordinary sessions is 50
private copies of a 6,100-token prompt.

`spawn_agent` takes two new fields for this: `knowledge` (files and notes several
agents need) and `instructions` (the role, shared by every agent of that kind).
Files in `knowledge` are read once and shared, not read again by every agent
with its own tool. On nodes without PolyKV, files are passed by name and agents
read what they need.

A full owner window is now a queue, not a failure. The agent waits the time
the engine names, or gets a second owner if the engine has room. An agent's
session, and the owner once its last agent ends, is released the moment the
work ends, not five minutes later.

## Compaction ran in the wrong sessions

A sub-agent's compaction used the lead's model and the lead's counts, and on
opencoti each summary call arrived with no session at all. Each one was an
anonymous admission of the model's whole window, two or three per compaction.
It now runs with the agent's own model, inside the agent's own session, one
call at a time. The shared turns at the head of an agent's conversation are
never summarised away.

## The agent strip

Running agents are now a line of tags: each shows a clock while it waits for a
slot and a spinner while it runs. Click a name to open its box, which has the
stop button, the node, and the last lines of what it is writing. The strip has a
height limit and scrolls, so fifty agents no longer push the chat off screen.
